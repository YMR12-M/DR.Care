## 💰 نظام التسعير في DR.Care

## نظرة عامة

السعر النهائي لأي حجز = سعر الباقة + إضافة نوع العربية − الخصم (كوبون و/أو خصم يدوي في POS).

**تحديث مهم**: أسعار الباقات لم تعد ثابتة في `config.php` — انتقلت لجدول `packages` في قاعدة البيانات، **قابلة للتعديل من لوحة الإدارة** (قسم "الباقات والأسعار"). أنواع العربيات (`carTypes`)، الفروع، وطرق الدفع لسه في `config.php` زي ما هي (خارج نطاق هذا التغيير).

## الملفات الأساسية

- **جدول `packages` (DB)** — مصدر الحقيقة الحالي لأسعار الباقات. مُعرَّف في `api/bootstrap.php` (`CREATE TABLE packages` + `seedPackagesIfEmpty()` اللي بتعمل seed لمرة واحدة من القيم القديمة في `config.php` أول مرة يتشغّل فيها). `code` الباقة ثابت غير قابل للتعديل بعد الإنشاء (مستخدم كمفتاح منطق أعمال في عدة ملفات، راجع القسم أدناه).
- `api/config.php` — لسه مصدر الحقيقة لـ: `carTypes`، `branches`، `paymentMethods`، `instapayNumber`. **مش** مصدر أسعار الباقات بعد الآن.
- `api/packages.php` — `GET` عام (بدون تسجيل دخول): يرجّع الباقات النشطة من جدول `packages` + باقي القيم من `config.php` في نفس شكل الـJSON القديم. `GET ?admin=1` (يتطلب أدمن): كل الباقات (نشطة ومعطّلة) بالـ`id`. `POST`/`PATCH`/`DELETE` (أدمن + CSRF): إنشاء/تعديل/تعطيل باقة — راجع قسم "إدارة الأسعار من لوحة الإدارة" أدناه.
- `api/bookings.php` / `api/pos.php` — يحسبان السعر عند إنشاء الحجز: الباقة تُقرأ الآن من جدول `packages` (`SELECT * FROM packages WHERE code=:code AND is_active=1`)، ونوع العربية لسه من `config.php`. نفس منطق الـ400 عند عدم التطابق كما كان.
- `api/pricing.php` — endpoint منفصل لحساب سعر باقة+نوع عربية بمعزل عن إنشاء حجز فعلي؛ فرع PHP fallback بتاعه اتحول برضه لقراءة جدول `packages`.
- `java/src/com/drcare/PricingCalculator.java` — حاسبة أسعار بلغة Java، يحاول `api/pricing.php` استدعاءها أولاً كـ "مصدر أساسي" قبل العودة لـ PHP.

## ⚠️ فجوة حرجة: `api/pricing.php` والـ Java Calculator غير متزامنين فعلياً — وربما غير مستخدَمين إطلاقاً

عند فحص الكود الفعلي تبيّن الآتي (ليس تخميناً):

1. **`api/pricing.php` غير مُستدعى من أي واجهة أمامية حالياً** — لا يوجد أي `fetch`/رابط لـ `pricing.php` في أي ملف `.html`/`.js` بالمشروع (بحث شامل). الـ endpoint موجود ويعمل لكنه غير مستخدَم فعلياً في أي تدفق حي.
2. **حتى لو استُخدم، أكواد الباقات في `PricingCalculator.java` لا تطابق `config.php` إطلاقاً**:
   ```java
   private static final Map<String, Integer> PACKAGES = Map.of(
       "quick", 150, "full", 280, "detail", 650, "fleet", 0
   );
   ```
   بينما الأكواد الفعلية المستخدمة في كل الموقع هي `inside-out`, `outside`, `deep`, `cover`, `rims`, `engine`, `chemical`, `carpet`, `blanket`. لا تقاطع بين القائمتين إطلاقاً.
3. **النتيجة العملية:** في `api/pricing.php`، السطر:
   ```php
   $p = PACKAGES.getOrDefault(pkg, 280); // داخل Java
   ```
   يستخدم `getOrDefault` وليس استثناء — أي كود باقة حقيقي (مثل `outside`) لن يُطابَق أبداً، وستُستخدم القيمة الافتراضية `280` بدل السعر الصحيح. بما أن Java يُعيد رقماً صالحاً دائماً (حتى لو غلط)، فإن **فرع الـ fallback إلى PHP في `pricing.php` لا يُستدعى عملياً أبداً** إذا كان الـ Java متاحاً على السيرفر — العميل سيحصل على سعر خاطئ (280 دائماً) بدل السعر الصحيح، إلا إذا لم يكن Java مثبتاً على السيرفر (عندها فقط يُستخدم `config.php` الصحيح كـ fallback).
4. أنواع العربيات (`sedan/suv/van/pickup`) **متطابقة فعلاً بالصدفة** بين الملفين (0/60/90/120) — المشكلة فقط في أكواد الباقات.
5. `tests/test_pricing_java.sh` نفسه يختبر بأكواد الباقات القديمة (`quick`, `full`, `detail`, `fleet`) — أي أنه يختبر منطقاً منفصلاً تماماً عن الأسعار الحقيقية المعروضة للعملاء، وينجح دائماً بينما التسعير الفعلي للموقع لا علاقة له بهذه القيم.

**الخلاصة:** تدفق الحجز الفعلي (`bookings.php`, `pos.php`) **آمن تماماً** من هذه المشكلة لأنه يقرأ الباقة من جدول `packages` مباشرة (بعد النقل من `config.php`)، بدون المرور عبر `pricing.php`/Java إطلاقاً. المشكلة معزولة في `pricing.php` وحده، وهو endpoint غير مستخدَم حالياً — لكنه فخ لأي تطوير مستقبلي يفترض أن `pricing.php` يعطي سعراً صحيحاً بالأكواد الحالية.

## 💸 إدارة الأسعار من لوحة الإدارة (قسم "الباقات والأسعار")

الأدمن يقدر يعدّل اسم/سعر أي باقة موجودة، أو يضيف باقة جديدة، من `admin.html`. التعديل بيأثر **فوراً وفعلياً** على السعر اللي بيتحاسب في `bookings.php`/`pos.php`/`packages.php` العام (اتفحص مباشرةً بعد النقل: تغيير سعر تجريبي انعكس فوراً في نفس الاستعلام اللي بيستخدمه الحجز).

✅ **تحديث**: `CarWash-POS/index.html` بقى **ديناميكي** — أزرار الباقات بتتبنى بـJS (`fetchPackages()` في `CarWash-POS/script.js`) من نفس `api/packages.php` العام، مع نسخة احتياطية ثابتة (`FALLBACK_PACKAGES`) لو الـfetch فشل. يعني الكاشير بيشوف نفس السعر المحدَّث من اللوحة فوراً.

⚠️ **قيد معروف ومقصود لسه قائم (قرار نطاق واعي، مش نسيان)**: تعديل السعر من اللوحة **لسه مبيأثرش تلقائياً** على كروت الباقات التسويقية الثابتة في `index.html` (سطور ~334-469) و`mobile.html` (سطور ~218-303) — نص السعر فيهم مكتوب HTML ثابت، ممكن يتعالج مستقبلاً بنفس أسلوب `CarWash-POS` (تحويلها لتُبنى ديناميكياً من `packages.php`).

كود الباقة (`code`) **غير قابل للتعديل** بعد الإنشاء عبر الواجهة — مستخدم كمفتاح منطق أعمال (تسعير متغيّر، تصنيف إيراد) في `script.js`، `mobile.js`، `CarWash-POS/script.js`، `mobile-app/src/screens/BookingScreen.jsx`، و`admin.js` (قسم "الإيرادات"). حذف باقة من اللوحة هو **تعطيل (soft-delete)** مش حذف حقيقي — الحجوزات القديمة مخزّنة باسمها الخاص في صفها فمش بتتأثر.

راجع `ROADMAP.md` — إما (أ) حذف `PricingCalculator.java` وendpoint `pricing.php` طالما غير مستخدَمين، أو (ب) تحديث أكواد الباقات في الملف الـ Java لتطابق `config.php` واستخدام مصدر بيانات مشترك بدل نسختين منفصلتين.

## واجهة API

### `GET api/packages.php` (عام)

```json
{
  "ok": true,
  "packages": [ { "code": "outside", "name": "غسيل خارجي فقط", "price": 100 }, ... من جدول packages، is_active=1 فقط ... ],
  "carTypes": [ ... من config.php ... ],
  "branches": ["قليوب — شارع العروبة"],
  "paymentMethods": ["كاش", "Instapay"],
  "instapayNumber": "01037957593"
}
```

### `GET api/packages.php?admin=1` (أدمن — كل الباقات بالـid، نشطة ومعطّلة)
### `POST api/packages.php` (أدمن+CSRF) — `{code, name, price}` → إنشاء باقة جديدة، 409 لو الكود مكرر
### `PATCH api/packages.php` (أدمن+CSRF) — `{id, name?, price?, is_active?}` — لاحظ عدم قبول `code`
### `DELETE api/packages.php` (أدمن+CSRF) — `{id}` — تعطيل (soft-delete)

### `GET/POST api/pricing.php?package=outside&car_type=suv` (غير مستخدَم حالياً في أي واجهة)

```json
{ "ok": true, "price": 160, "label": "160 جنيه", "source": "php" }
```

`source` يكون `"java"` أو `"php"` حسب توفر Java على السيرفر — لكن راجع التحذير أعلاه قبل الاعتماد على دقة القيمة عند `source: "java"`.
